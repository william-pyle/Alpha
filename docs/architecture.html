Alpha architecture

Alpha is an Electron Windows application. The React renderer handles presentation; the main process owns persistent data, terminal processes and local agent tools.

Area Ownership
electron/store.mjs Atomic JSON persistence, project/workspace paths, knowledge scopes, indexed retrieval, questions and messages.
electron/main.mjs Windows, bounded IPC methods, file protocols, PTY lifecycle, local authenticated tool endpoint.
electron/providers.mjs Installed executable detection and per-session Codex/Claude MCP configuration, without global configuration changes.
integration/alpha-tools.mjs Stdio MCP tools, bundled into a standalone CommonJS program so packaged providers need no system Node installation.
src/ Application shell, terminal panes, questions, theme editing and Three.js graph.
public/art/ Alpha vector icon and generated theme artwork. Icon build outputs are deterministic derivatives of the vector source.

Boundaries

The renderer is sandboxed with context isolation and no Node integration. A preload exposes specific IPC operations. IPC validates the sending main frame. Application assets use a custom secure protocol. Project previews use a different protocol and a sandboxed iframe. Resolved paths must remain within the selected project's real directory.

Each terminal session receives a random local tool token. The HTTP endpoint binds only to loopback. Agent methods derive project scope from the authenticated session, not caller-supplied IDs. Agents may ask questions and read human answers but cannot create human answers. Cross-project agent messaging is rejected.

Persistence and retrieval

A single app instance owns each data root. State is saved through a temporary file and atomic rename. Projects and workspaces are separate physical directories. Failed state parsing stops startup instead of overwriting data. The local inverted term index is rebuilt on knowledge edits; retrieval filters by project before scoring and budgeting. Shared records cannot link to another project's private records.

Provider behavior

Codex receives per-session MCP configuration overrides and concise workflow instructions; Claude Code receives per-session MCP configuration and appended instructions. Neither path chooses a model or bypasses existing permissions. Calls and account access happen only when the user runs a provider. The bundled tool program uses Electron in Node mode, so the portable build does not depend on a separate system Node executable.

Build and checks

TypeScript compilation, data/permission tests, bundled MCP transport checks, and isolated Electron desktop tests cover real PowerShell/Git Bash sessions, layouts, scope filtering, questions, viewer docking and sandboxed HTML. Test profiles and screenshots are ignored by Git. Use the bundled desktop runtime on Windows; no active external agent conversations are needed for these checks.

Installer and update delivery

GitHub Actions builds a per-user NSIS installer. Stable version tags that match package.json publish the installer, blockmap and latest.yml together. The packaged app-update.yml pins the feed to william-pyle/Alpha. electron-updater validates download checksums; an Authenticode certificate has not yet been configured. Release write access exists only in the publishing job. Neither source nor application contains a GitHub token.

The main process owns UpdateController and all network/installer actions. Renderer IPC exposes only check, download, defer, install and the fixed release page. Both autoDownload and autoInstallOnAppQuit are false. Restart requires a native confirmation, with an active-window count. Checks run after 15 seconds and every six hours; concurrent operations are suppressed. Development, portable and isolated test runs do not auto-update.
