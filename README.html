Alpha

A Windows workspace for agent windows, projects and connected knowledge.

Package: com.jazcosolutions.alpha · Version: 0.1.1

Run the app

Anything created for or by Alpha uses com.jazcosolutions as its default namespace prefix unless you specify another.

Download Alpha-Setup-0.1.1-x64.exe from GitHub Releases and run the installer. It installs for your Windows user and adds Start menu and desktop shortcuts. Install Codex, Claude Code or Git for Windows separately to use those providers; Windows PowerShell is detected automatically.

Build from source

Use Windows 10 1809 or later / Windows 11, Node.js 24 and npm.

npm ci
npm run build
npm start

To run checks and build the Windows installer:

npm test
npm run test:desktop
npm run package

The build uses the official node-pty package's precompiled Windows Node-API binaries. No native rebuild is needed for this x64 release.

Included

  • New window: Codex, Claude Code, PowerShell and Git Bash, with New Project selected by default.
  • Project-owned workspaces, simultaneous left/right, top/bottom, grid and tab layouts.
  • Dockable project-themed file and memory viewer.
  • Shared and project-specific memory and skills, local ranked retrieval, a live navigable 3D memory graph.
  • Central Questions inbox with human answers and requester delivery.
  • Window messaging through inboxes and a scoped local MCP integration.
  • Alpha, Smurfs and Rena / Higurashi themes, controller artwork, theme editor and custom icons.

Data and Git

User data lives in the Alpha application data folder, separate from source. On a standard Windows installation this is %APPDATA%/Alpha. Open it through Settings. Projects contain workspaces/. Knowledge, questions, settings and session records are stored in alpha.json; terminal history is under sessions/.

The repository excludes dependencies, binaries, generated bundles, test profiles, credentials and runtime data. Builds land in release/. The included Windows workflow builds and checks an installer on pushes to main and pull requests. Version tags publish a tested installer and its update metadata to GitHub Releases.

Updates and releases

The installed app checks GitHub after startup and every six hours. You can also use Settings → Check for updates. Download starts only when you choose it; restarting to install requires a separate confirmation. Running agent and shell windows stop on restart. Saved data is retained. The optional portable edition (npm run package:portable) requires installing the setup edition to receive automatic updates.

To release a new version, update package.json and package-lock.json, commit, then push a matching stable version tag: 

npm version patch
git push origin main --follow-tags

GitHub Actions checks that the tag matches the package version, runs tests, builds the NSIS installer, validates its SHA-512 and feed, and publishes Alpha-Setup-VERSION-x64.exe, its blockmap and latest.yml together. Main-branch artifacts are not updates. Publishing uses GitHub's temporary workflow token; no credential is embedded in the application. The current installer is unsigned.

How it works

See the user guide and architecture notes.

Provider accounts, models and permission settings remain with their installed tools. Alpha does not bypass them. Generated visual assets are included under public/art. The character themes contain original illustrations of their named fictional characters.
